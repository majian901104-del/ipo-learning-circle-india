# V3.6 single-primary dynamic WhatsApp routing

## What changes
- Main group A is already configured by owner in production D1. New visitors reaching Cloudflare Worker `/join` use `link_state.active_url` from `angel-research-links-v33` (production), instead of fixed `COMMUNITY_DESTINATION=cc.stockscode.click`.
- Back-up B is OPTIONAL. Its absence does not affect joining the currently configured main group.
- Unified V3.5 dashboard now permits `PUT /admin/links/primary` even after initialization; this performs CAS update via D1 version and appends old/new destinations to audit history. It shows a prominent confirmation. No redeployment is needed to replace A.
- Existing /join query attribution (`c`, `s`, `m`, etc.), no-store redirect, DNT/GPC behavior remain unchanged.
- This stage DOES NOT enable the India-IP or social-origin admission gate (`LINK_MODE_ENABLED=false`) and DOES NOT activate IP statistical dedup (`ANALYTICS_IP_DEDUP_ENABLED=false`).
- Do not claim hidden WhatsApp invitations cannot be forwarded. Admin approval to join in WhatsApp remains important.

## Release safeguards
- `LINK_DYNAMIC_TARGET_ENABLED=true` is the only activated routing flag. This reads `LINK_DB` on each `/join` and validates the stored URL host.
- Missing or malformed D1 main URL, network errors, missing table/binding => 503 (no redirect, no silent fallback to old link).
- Existing current group A must be set before deployment; screenshot of V3.5 owner dashboard shows saved A (masked).
- If legitimate visitors encounter errors, use GitHub/Cloudflare rollback by reverting `LINK_DYNAMIC_TARGET_ENABLED=false`, then deploy. This re-enables OLD redirect and should only be used as a short emergency measure if the old URL is still valid.
- Main replacements take effect for new requests; browsers already at WhatsApp are not retroactively migrated.

## Browser acceptance
1. Open https://angelresearchindia.com/analytics-dashboard.html and Ctrl+F5. Log in with existing LINK_ADMIN_KEY.
2. Visit 群链接管理; confirm A marked 已配置, B may show 暂无备用; footer says 主群动态跳转已开启.
3. Click 检查状态: the report status should show 动态主群模式. Public `/health` routeMode should be `dynamic_primary`.
4. With a personal allowed test account and suitable network, click a REAL website group CTA, verify it opens main A in WhatsApp. Do not expose full invite URL in screenshots.
5. Do not change actual A unless a genuine replacement group exists. For future replacement, enter next group under primary A, confirm, and check the new CTA redirects.
6. Confirm no new admin key is needed and there is no accidental extra click counting. Country/social admission and IP stats dedup stay OFF.
