# V3.5 Unified Administrator Login

**Single sign-in without any new administrator password.** The existing Cloudflare Worker secret `LINK_ADMIN_KEY` becomes the owner credential. It is posted only to `/admin/session` from the website's permitted origins and is never stored in the browser's persistent storage. Cloudflare Worker signs a four-hour token; the browser keeps only this temporary session token in memory.

## What this version provides
- Once logged in, Analytics reports and main/backup WhatsApp group controls use the SAME temporary credential.
- Cloudflare Worker verifies HMAC signature, expiration, owner role, and token format on each protected request. Redirect to WhatsApp still works as before, independent of login.
- Logout clears local in-memory session; the signed bearer token itself is stateless and remains technically usable until expiry if stolen. Rotate LINK_ADMIN_KEY to revoke all sessions in an emergency.
- Legacy REPORT_ACCESS_KEY and LINK_ADMIN_KEY bearer endpoints are retained for rollback. Do not remove secrets immediately.
- No new D1 table, no cookie, no third-party identity provider, and no new browser login password.

## Important security and operational caveats
- This interim owner-only login is **not Cloudflare Access, MFA or staff-role RBAC**. If multiple staff need access, migrate to a managed identity provider with MFA, scoped roles and an audit log.
- The site is static GitHub Pages; hiding admin HTML is NOT an authorization boundary. All protected Worker actions continue to verify server-side token/signed secret.
- Login attempts must eventually be rate-limited in Cloudflare security rules. A high-entropy LINK_ADMIN_KEY protects against password guessing, but rate limiting should still be configured.
- Prefer owner sign-in only on a trusted device. Compromised browser JS or an injected script could capture tokens. Maintain CSP and monitor dependencies.
- Current analytics statistical IP dedup remains OFF until ANALYTICS_IP_HASH_KEY is separately configured, along with its schema. That secret is a server HMAC key, not a login password.
- The old link-management.html redirects to the same analytics-dashboard.html#links module.

## Owner acceptance
1. Open https://angelresearchindia.com/analytics-dashboard.html and Ctrl+F5.
2. Enter the EXISTING `LINK_ADMIN_KEY` once in the unified sign-in, not the REPORT_ACCESS_KEY.
3. Verify reporting loads and the left sidebar group link settings show D1 main/backup without asking for the second password.
4. Sign out using the dashboard Lock action and verify both report and group management close.
5. Wait four hours or rotate LINK_ADMIN_KEY to expire sessions; further reports and link edits must return HTTP 401.
6. Confirm public WhatsApp /join redirects are unchanged and runtime flags still disabled until separate rollout.
