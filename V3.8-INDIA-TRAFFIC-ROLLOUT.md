# V3.8 India-only community entry and analytics-only IP dedup

**Main traffic path stays V3.7.1:** website → /join → name + Indian WhatsApp phone → required privacy consent → D1 → confirmation + auto/manual WhatsApp group A handoff.

## Production flags
- JOIN_INDIA_ONLY_ENABLED=true: Cloudflare checks request.cf.country on GET and POST /join. Visitors outside India, and unknown-geo cases, receive HTTP 403 before seeing the form or submitting data. Owner/admin APIs are unaffected.
- ANALYTICS_IP_DEDUP_ENABLED=true: same Cloudflare public IP counted once for page_view and once for join_click in independent 24h rolling windows. Repeat visitors **may still register and access WhatsApp**, not counted as additional click stats. Not a per-person or per-phone unique metric. Historical counts are NOT retroactively deduplicated.
- JOIN_SOURCE_POLICY=observe: records declared campaign source only, **not verified platform provenance**. X/Facebook/Instagram/YouTube referral and query parameters alone can be absent or spoofed. Strict source proof still needs separate first-party entry/click-token campaign QA and cannot completely stop forwarding of an original WhatsApp invite.
- LINK_MODE_ENABLED=false: do not enable the old /entry challenge (it hijacks the existing functioning registration flow). Existing direct D1 main group routing remains ON.

## No extra owner password
For analytics HMAC only, Worker derives a purpose-separated pseudonym from existing LINK_ADMIN_KEY when ANALYTICS_IP_HASH_KEY is not configured. Raw IPs and names never enter analytics; HMAC digest rows expire after 24 hours. Rotating LINK_ADMIN_KEY may reset the dedup window; owners do not type additional secrets. Existing optional dedicated stats HMAC key still takes precedence.

## Auto-migration
On first tracked request, if analytics_ip_dedup table is missing, Worker bootstraps exactly the table and expiry index with CREATE IF NOT EXISTS statements. No manual D1 console work is normally required. A Cloudflare D1 schema/permission failure suppresses that statistical event but **does not block registration or WhatsApp access**. Inspect D1 status after production release.

## Required checks before ad budget
1. Open admin from any country and confirm group A and D1 status; visit /health and verify inviteIndiaOnly=true, ipDedupEnabled=true, ipDedupReady=true.
2. Test with a device on a **genuine Indian network**: new GET /join must render registration, POST should save to D1 and WhatsApp main A should open via success page.
3. Test a non-Indian network GET /join: should return HTTP 403. Do not assume VPN locations equal actual location.
4. Use one Indian IP and click twice: both registrations remain possible, while 24h aggregate page_view or join_click increments at most once.
5. Confirm paid campaign links deliver 'source' and 'campaign' labels; they do NOT authenticate social provenance. Use WhatsApp admin approval and moderation, while exploring abuse limits and stronger campaign proof.
6. If false positives affect legitimate Indian visitors, immediately roll back JOIN_INDIA_ONLY_ENABLED to false; if stats show missing configuration, roll back ANALYTICS_IP_DEDUP_ENABLED to false while investigating.
