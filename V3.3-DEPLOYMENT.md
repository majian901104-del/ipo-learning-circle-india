# V3.3 implementation / activation notes

PRODUCTION IS NOT YET ACTIVATED. This branch includes the API, responsive link-control admin, client-side join gate and tests. GitHub Pages and Cloudflare Worker are deployed separately.

Provision a new Cloudflare D1 database named angel-research-links-v33. Execute conversion-worker/migrations/0001_v33.sql, bind D1 as LINK_DB, and set a fresh independent Cloudflare secret LINK_ADMIN_KEY (64+ random chars). Do not disclose the key to chat or store it in GitHub.

Add SHORTLINK_ALLOWLIST as a comma-separated list of approved controlled hostnames, or leave it empty to accept only official WhatsApp invite URLs.

Deploy updated Cloudflare Worker with LINK_MODE_ENABLED=false initially; use /admin/links via the link-management.html portal to save a current primary and standby. Set LINK_MODE_ENABLED=true only after front-end deployment is coordinated. Without real Cloudflare account access we CANNOT provision or deploy this backend.

New approved social campaign links must use worker /entry?s=x&c=campaign (similarly facebook, instagram, youtube). Referrer signals can be missing in some in-app browsers: STRICT deny-by-default can reject legitimate visitors. Do genuine tests on Indian mobile connections for all four platforms.

A legitimate social user receives a one-time 15-minute admission token, and the worker requires cf.country=IN again at /join. Existing advertiser URLs pointing directly to angelresearchindia.com with only UTM tracking will NOT provide V3.3 admission, and should be updated before launch.

Copying the actual final WhatsApp invitation remains possible after a successful redirect. Enable WhatsApp admin approval. Rotate invites in WhatsApp if leaked. Do not claim the website controls WhatsApp memberships.

Deployment needs: Cloudflare D1 identifier/binding, separately configured LINK_ADMIN_KEY secret, production Worker release access, tested ad-link migration, mobile tests. Production V3.2 remains unchanged while this work is on the feature branch.
