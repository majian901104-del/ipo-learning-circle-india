# V3.4.2 IP dedup — analytics ONLY, not a group access restriction

Changes from V3.4.1: an IP can open /join repeatedly. The first consented page view and first consented group redirect count once each per public network IP during a rolling 24h window. Old version's 429 denial is removed, including when the deprecated LINK_IP_DEDUP_ENABLED flag is true.

## Enabling (disabled by default)
1. In Cloudflare D1 production database **angel-research-links-v33** -> Console, execute conversion-worker/migrations/0003_v342_statistics_ip_dedup.sql. The old link_ip_limits table is not used.
2. Worker -> Settings -> Runtime variables and secrets: create a strong independent Secret named ANALYTICS_IP_HASH_KEY (at least 32 chars). Store outside GitHub; never send it in chat.
3. After migration/secret, set ordinary runtime ANALYTICS_IP_DEDUP_ENABLED=true and ANALYTICS_IP_DEDUP_HOURS=24. Keep LINK_IP_DEDUP_ENABLED=false (deprecated) and keep LINK_MODE_ENABLED unchanged.
4. Sync new ordinary config to conversion-worker/wrangler.toml before future GitHub deployment. The deployed source defaults to false, so a later build can overwrite a manual toggle.
5. Verify with distinct test public IPs: first page_view counted, second suppressed; first join_click counted, second suppressed; BOTH /join redirects return HTTP 302. No 429 block.
6. Cloudflare Cron deletes expired pseudonyms daily; a 24-hour rolling window starts with first accepted event. Source attribution belongs to the first campaign/source that generates the counted event within the window.

## Accuracy/privacy
- This is count of public IPs per rolling 24h, not distinct individuals, unique devices, actual joined WhatsApp members, or confirmed ad impressions.
- Indian CGNAT/carrier Wi-Fi can put many unrelated people behind one IP, undercounting traffic; dynamic IPs can overcount the same person.
- Analytics Engine is aggregate event only; keyed hash + expiry stored in D1; no raw IP saved. DNT/GPC requests are not recorded.
- Existing history was anonymous aggregate data. It cannot be deduplicated retrospectively. Data spanning the activation time blends raw and post-activation IP-dedup counting. Mark this in dashboard.
- Non-counting does not disable entry. Separate India/source requirements are controlled by LINK_MODE_ENABLED and must be tested independently.
- If database or secret unavailable with the analytics dedup switch enabled, suppress new analytics events rather than writing inaccurate figures; never break the WhatsApp redirect.
- Update privacy notice before enabling: explain keyed-IP statistics anti-duplication, time window and retention.
