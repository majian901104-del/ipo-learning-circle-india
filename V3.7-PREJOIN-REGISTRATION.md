# V3.7 pre-WhatsApp lead registration

**Production rollout 15 October 2026**: `JOIN_LEAD_FORM_ENABLED=true` in Wrangler after owner shared proof of successful production D1 table + index creation, then confirmed support@angelresearchindia.com receives incoming mail. Current /join displays the form, and successful D1 insert redirects to live main group A. No new admin login secret is required.

## New user journey
Website CTA -> Worker GET /join -> branded required Full Name + Indian WhatsApp number (+91 and 10 digit local) -> required specific invitation data-processing checkbox -> optional research updates checkbox (unchecked by default) -> POST to same Worker /join -> D1 writes personal data -> 200 confirmed registration page (automatic 2-second refresh plus manual WhatsApp button) -> current dynamic main group A. The original 303 was blocked in some Chromium browsers by the strict form-action 'self' CSP policy.

Data uses HTTPS form POST body only. The name and phone never appear in the query string, Analytics Engine, WhatsApp redirect Location, or public HTML. One-time HMAC form token uses the **existing LINK_ADMIN_KEY** (not an additional administrator login password). A replay of the same signed form and same submitted identity produces no additional record and resumes the success page; resubmission with a different identity is rejected. No public IP is stored with contact records.

## Private owner records
V3.7 dashboard adds 客户登记 (customer registrations): newest 50 per page, CSV export of current page after confirmation, DELETE one record. All operations require V3.5 signed owner admin session, not public access. Records are deleted by daily Cron after 90 days. This is consent to process invitation, not proof of actual WhatsApp membership.

## Compliance and limits
- Indian DPDPA or other relevant requirements depend on deployment dates and applicability: obtain legal/privacy review for exact notice and grievance/withdrawal procedure before activation.
- This flow deliberately does not send unsolicited messages unless the optional outreach checkbox was selected; consent for invitation is not marketing permission.
- The WhatsApp original invite can still be forwarded by someone who receives it. WhatsApp admin approval is separate.
- A form is not proof of a unique person or a real WhatsApp join. India IP and verified social origin controls have not been enabled.
- Existing `/apply.html` Google Apps Script research-update form remains separate and unchanged; community onboarding does not add age, email or investment information fields.

## V3.7.1 redirect reliability hotfix
The form document keeps a restrictive `Content-Security-Policy: form-action 'self'`. Chromium may block the earlier POST-to-external-site 303 redirect even after D1 save. The server now returns an independent 200 success page, automatically navigates after 2 seconds via HTML meta refresh, and shows a manual WhatsApp button for browsers that suppress automatic cross-site navigation. GET form still hides the group URL; only a registered visitor receives the success page. The same signed form replay returns the success page without new D1 writes or additional click events. This avoids needless repeated registrations.
